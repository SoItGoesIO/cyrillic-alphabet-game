# CLAUDE.md

## Project Overview

Cyrillic Alphabet Game — gamified learning app with full-stack architecture. Local dev runs in WSL2 with Docker + Supabase. Production deploys to Netlify with live Supabase backend.

## Tech Stack

- Dev environment: WSL2 (Ubuntu), Docker Engine (no Docker Desktop)
- Database: PostgreSQL via Supabase (local + live)
- Backend: Supabase (PostgREST API, Auth, RLS)
- Frontend: React 18 (CDN), Vanilla JS ES modules, Tailwind CSS
- Deployment: Netlify (frontend) + Supabase (backend)
- Tooling: Makefile + scripts, npm, Docker

## Project Structure

- `database/` — SQL schema and migrations (source of truth)
- `src/` — modular JS source (auth, db, gamification, ui, game)
- `scripts/` — start/stop/status/reset/test shell scripts
- `audio/` — Cyrillic letter pronunciation files (01.mp3-33.mp3)
- `Makefile` — unified dev commands (start/stop/status/reset/db-shell/test-queries)
- `.env.local` — auto-generated by Supabase for local dev (git-ignored)
- `.env.private` — LIVE secrets for deployment (git-ignored)

## Development Commands

- `make dev` — start local Supabase stack (calls `scripts/start.sh`)
- `make status` — show service status and connection details
- `make db-shell` — connect to local PostgreSQL
- `make reset` — reset local database with confirmation
- `make test-queries` — populate sample data and run tests
- `make stop` — stop local services cleanly

## Workflow Guidelines

- **Local stack** managed outside Claude (long-running processes)
- **Claude runs short commands only** — edits, migrations, quick tests
- Database changes: edit in `database/`, apply via scripts
- Local development: `make dev` → edit → test → commit
- Production deployment: Netlify auto-deploy + manual Supabase push

## Environment Setup

- WSL2 Ubuntu with Docker Engine working
- Node.js 20+, Supabase CLI via `npx supabase`
- Local URLs: API http://127.0.0.1:54321, DB 127.0.0.1:54322, Studio http://127.0.0.1:54323
- Environment loading: `npx supabase status -o env | tee .env.local` (local)
- LIVE environment: `set -a; source .env.private; set +a` (session-only)

## Do Not Section (Critical)

- **Do NOT** start/stop Docker or run `npx supabase start/stop` from Claude
- **Do NOT** print or persist secrets (ANON_KEY, ACCESS_TOKEN, SERVICE_ROLE)
- **Do NOT** commit `.env.local`, `.env.private`, `.env.production`
- **Do NOT** run `sudo` or commands outside repo without confirmation
- **Do NOT** run long-duration commands (>60s) — ask user to run in Terminal A

## Instructions for Claude

- Always use `npx supabase` (no global CLI installs)
- Read environment variables from files/status, never echo secret values
- For database tests: use local credentials from `npx supabase status -o env`
- Stop immediately on SQL errors and show failing statement
- Before LIVE operations, show what changes will be applied
- Use existing Makefile targets when possible instead of raw commands

## Environment Variables (names only)

**Local (auto-generated)**:

- `API_URL`, `ANON_KEY`, `DB_URL`, `STUDIO_URL`, `SERVICE_ROLE_KEY`

**LIVE (in .env.private)**:

- `SUPABASE_PROJECT_REF`, `SUPABASE_ACCESS_TOKEN`
- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY` (server-side only)

## Security Guidelines

- Secrets only in `.env.private` (mode 600, git-ignored)
- Never expose service role key to frontend
- Rotate keys immediately if accidentally shared
- Use RLS policies for all user data access

## Architecture Notes

- **XP System**: Levels 1-6+ with thresholds (0, 100, 250, 500, 900, 1400+ XP)
- **Task Management**: created → in_progress → completed status flow
- **Cyrillic Learning**: 33 letters with difficulty-based XP rewards
- **Authentication**: Supabase Auth with magic links + password
- **Database**: PostgreSQL with RLS, atomic operations, audit logging
