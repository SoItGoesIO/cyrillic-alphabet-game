# CLAUDE.md

## Project Overview

Cyrillic Alphabet Game — local dev stack runs in WSL2 with Docker. Supabase provides DB/PostgREST/Studio. This repo includes Make targets and scripts to manage local dev. We also link to a LIVE Supabase project for deployment.

## Tech Stack

- Dev environment: WSL2 (Ubuntu with systemd)
- Infra: Docker Engine (no Docker Desktop), Supabase CLI (via `npx`)
- Database: Postgres (Supabase local), SQL migrations in `supabase/migrations`
- API: PostgREST (Supabase REST at http://127.0.0.1:54321)
- Admin UI: Supabase Studio (http://127.0.0.1:54323)
- Tooling: Makefile + scripts (`scripts/*.sh`)

## Project Structure

- `supabase/migrations/` — schema changes (source of truth)
- `scripts/` — start/stop/status/reset/test shell scripts
- `Makefile` — `start/stop/status/reset/db-shell/test-queries/logs/ps/db-dump`
- `.env.local` — auto-generated by Supabase for **local** (git-ignored)
- `.env.private` — **LIVE** secrets for CLI/linking (git-ignored)

## Development Commands

- `make dev` — start local stack (calls `scripts/start.sh`) **(Run in raw WSL, not from Claude)**
- `make status` — show local status
- `make db-shell` — psql into local DB
- `make reset` — reset local db (`--force`)
- `make stop` — stop local stack
- `make ps`, `make logs`, `make db-dump` — diagnostics

## Workflow Guidelines

- **Local** stack is managed outside Claude (long-running). Claude can run **short** commands only.
- Migrations: edit in `supabase/migrations`, apply with `npx supabase migration up` (local) and `npx supabase db push` (LIVE).
- For LIVE: link once with `npx supabase link --project-ref <REF>` (reads token from env), then `npx supabase db push`.

## Environment Setup

- Node 20+, Docker Engine working in WSL: `docker run --rm hello-world`
- Supabase CLI via `npx supabase --version` (2.x)
- Local env via `npx supabase status -o env | tee .env.local`
- LIVE envs in `.env.private` (git-ignored), loaded per session:  
  `set -a; source .env.private; set +a`

## Do Not Section (important)

- **Do NOT** start/stop Docker or `npx supabase start/stop` from Claude.
- **Do NOT** print or persist secrets (ACCESS_TOKEN, SERVICE_ROLE).
- **Do NOT** commit `.env.local`, `.env.private`, `.env.production`, `supabase/.temp`.
- **Do NOT** run `sudo` or destructive commands without explicit confirmation.

## Instructions for Claude

- Always prefer `npx supabase` (no global installs).
- Use environment variables already set in session; never echo secret values.
- For REST tests, read ANON key via `npx supabase status -o env` (local) or from environment (LIVE).
- If a command could run >60s (image pulls, start), ask me to run it in the other window.
- Before pushing to LIVE, show which migrations will run. Stop on first SQL error and show the failing statement.

## Environment Variables (names only; examples)

- `SUPABASE_PROJECT_REF` (LIVE)
- `SUPABASE_ACCESS_TOKEN` (LIVE)
- `NEXT_PUBLIC_SUPABASE_URL` (LIVE)
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` (LIVE)
- `SUPABASE_SERVICE_ROLE_KEY` (server-only, LIVE)
- Local (auto): `API_URL`, `ANON_KEY`, `DB_URL`, etc from `npx supabase status -o env`

## Security

- Keep secrets only in `.env.private` (mode 600). Never commit.
- Rotate keys if shared publicly. Never expose service role key to the frontend.

## Plan Mode (safe exploration)

For big refactors or codebase exploration: use read-only planning first; propose a step plan, then execute in small batches (file edits, then tests).

Create: .claude/commands/rls-propose.md

# Propose RLS policy for profiles

1. Print existing policies:

SELECT schemaname, tablename, policyname, cmd, qual, with_check
FROM pg_policies WHERE schemaname='public' AND tablename='profiles';

2. Offer two options (ask before applying):

- Dev-read:
  ```
  ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;
  CREATE POLICY public_read_profiles ON public.profiles FOR SELECT USING (true);
  ```
- Auth-scoped:
  ```
  ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;
  CREATE POLICY read_own_profile ON public.profiles
  FOR SELECT USING (user_id = auth.uid());
  ```
